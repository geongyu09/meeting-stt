# 프로젝트 노트

`docs/`는 프로젝트마다 요구사항, 결정, 산출물, 회고를 모으는 곳이다. 허브는 `docs/index.md`, 새 노트의 틀은 `docs/_template/index.md`다.

```
docs/
├── index.md              # 허브 (진행 중 / 끝남 표)
├── _template/index.md    # 새 프로젝트 노트의 틀
└── <slug>/
    ├── index.md          # 프로젝트 노트 (필수)
    ├── requirements.md   # 필요할 때
    ├── decisions.md      # 필요할 때
    ├── design/           # 필요할 때
    └── retrospective.md  # 필요할 때
```

## 새 프로젝트

1. 아직 모르는 것만 한 번에 묻는다: 이름, 한 줄 설명, slug(영어 소문자와 하이픈, 예: `team-blog`), 역할, 관련 링크, 정기 일정, 시작일(기본은 오늘).
2. `docs/<slug>/`가 이미 있는지 확인한다. 있으면 새로 만들지 않고 알린다.
3. `docs/_template/index.md`를 읽고 값을 채워 `docs/<slug>/index.md`에 쓴다. 모르는 값은 `—`로 둔다.
4. `docs/index.md`의 "진행 중" 표에 행을 더한다.
5. 사용자의 현재 활동이 바뀐 것이므로 `profile/work/current.md`에 이 프로젝트와 노트 링크를 더할지 묻는다 (`profile` 스킬 절차).

## 상태 갱신

- 사용자가 말한 필드(다음 마감, 진행 중인 일, 막힌 것, 링크)만 고친다.
- 한 일, 결정, PR, 회의 같은 시간순 기록은 `## 작업 로그`에 덧붙인다. `### YYYY-MM-DD ~ YYYY-MM-DD` 기간 소제목 아래에 한 줄씩 적고, 위에 있는 기록은 고치지 않는다.
- 파일 링크는 `## 산출물`에 둔다. 작업 로그와 섞지 않는다.
- 다음 마감이 바뀌면 `docs/index.md` 표도 함께 고친다. 마감이 있는 일이면 `todo` 스킬로 `tasks.md`에도 넣을지 묻는다.
- `requirements.md` 같은 산출물 파일은 사용자가 필요하다고 할 때만 만든다.

## 목록

`docs/index.md`의 표를 보여 주고, 필요하면 각 노트의 "현재 상태"에서 다음 마감과 진행 중인 일을 함께 보여 준다.

## 종료

1. `docs/<slug>/index.md`의 메타를 `상태: 종료`, `종료일: YYYY-MM-DD`로 고친다. 폴더는 지우지 않는다.
2. `docs/index.md`에서 행을 "진행 중" 표에서 "끝남" 표로 옮긴다.
3. 회고가 있으면 다른 일에도 쓸 수 있는 교훈을 `wiki/`나 `profile/mind/insights.md`로 보낼지 묻는다.
4. `profile/work/current.md`에 이 프로젝트가 있으면 정리할지 묻는다.

## 주의

- 프로젝트의 오래가는 사실(역할, 정기 일정)은 `profile/work/current.md`가 원본이고, 노트에는 작업 기록을 둔다. 같은 정보를 두 곳에 길게 적지 않는다.
- 여러 파일을 한 번에 고치면 무엇을 어디에 고쳤는지 답변에 표로 보여 준다.
