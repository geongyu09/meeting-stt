# 글 개요와 초안

사용자 대신 글을 쓴다. 결과는 `raw/`에 저장하고, 문체는 `profile/communication/style.md`를 따른다.

## 절차

1. 방향을 확인한다. 요청에 이미 있는 것은 다시 묻지 않고, 빠진 것만 한 번에 묻는다.
   - 글의 목적과 종류(블로그, 메일, 회고, 발표 등)
   - 읽는 사람
   - 전하려는 말
   - 길이와 깊이

   사용자가 무엇을 생각하고 느꼈는지는 짐작하지 않는다. 모르면 묻는다.

2. 재료를 모은다.
   - 사용자의 경험이나 생각이 필요하면 `profile/`(회고, 교훈, 현재 활동)과 `docs/`, `raw/`에서 관련 기록을 찾는다. 찾은 재료로 글을 짜도 되는지 사용자에게 확인한다.
   - 사실 정보가 필요하면 `wiki/`를 먼저 보고, 부족하면 다른 자료를 찾되 출처를 적는다.
3. 개요를 쓴다. 이 글의 중심 메시지를 한 문장으로 정하고, 도입, 본문 부분들, 맺음의 뼈대를 목록으로 짠다. 결과는 `raw/[outline] 글 제목.md`에 저장한다.

   ```text
   # 글 제목

   ## 읽는 사람
   ## 전하려는 말
   ## 구성

   [도입]
   - ...

   [1부: ...]
   - ...

   [맺음]
   - ...
   ```

4. 사용자가 본문까지 원하면 개요를 따라 초안을 쓰고 `raw/[draft] 글 제목.md`에 저장한다.
5. 저장한 뒤 `profile/communication/style.md`의 `## 글쓰기`와 `## 쓰지 않는 표현`에 맞는지 한 번 더 읽고 고친다.
6. 답변에는 저장한 경로와, 사용자가 채워야 할 부분(경험, 수치, 이름 등)을 짧게 알린다.

## 주의

- 사용자의 경험을 지어내지 않는다. 자리를 비워 두고 `{여기에 겪은 일}`처럼 표시한다.
- 고쳐 달라는 피드백이 반복되면 `style` 스킬로 문체에 기록할지 묻는다.
