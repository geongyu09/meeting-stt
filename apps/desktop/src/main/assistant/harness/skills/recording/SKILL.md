# 녹음 원문 정리

앱은 녹음이 끝나면 전사 원문을 `raw/recordings/<YYYY-MM-DD-HHmm> <주제>.md`에 저장한다. 원문은 머리말(종류, 제목, 시작, 길이, 참석자)과 본문으로 되어 있고, 사용자가 녹음하며 적은 `## 노트`가 있을 수 있다.

## 절차

1. 원문을 읽는다. 회의면 화자별 발언을, 메모면 사용자 혼자 남긴 말을 본다.
2. `## 노트`가 있으면 전사보다 믿을 만한 단서로 본다. 이름과 용어 표기, 결정, 할 일은 노트를 따른다. 노트의 링크는 열 수 있으면 읽고 정리에 반영하고, 정리한 문서에 링크도 함께 적는다. 열 수 없으면 링크만 적고 읽지 못했다고 쓴다.
3. 원문 머리말 바로 아래에 `## 요약` 섹션을 쓴다. 원문 본문은 지우거나 고치지 않는다.

   ```markdown
   ## 요약

   {무엇에 관한 기록인지 2~4문장}

   ### 결정

   - ...

   ### 할 일

   - ... (누가, 언제까지)

   ### 반영한 곳

   - `tasks.md`: 할 일 2개 추가
   - `docs/<slug>/index.md`: 작업 로그 1줄

   ### 확인 필요

   - ...
   ```

   해당하는 내용이 없는 하위 섹션은 뺀다.

4. 알맞은 문서로 보낸다.
   - 사용자가 맡은 할 일 중 마감이 있는 것은 `todo` 스킬 형식으로 `tasks.md`에 더한다. 마감이 불분명하면 `— 마감 미정`으로 적고 "확인 필요"에 남긴다.
   - 진행 중인 프로젝트(`docs/index.md`)와 관련된 결정과 진행은 그 프로젝트 노트의 `## 작업 로그`에 한 줄로 덧붙이고 원문 경로를 링크한다.
   - 나중에 공부할 주제가 나오면 `backlog.md`에 더한다.
   - 사용자에 대한 새 사실(새 프로젝트, 목표, 습관 등)은 `profile/`을 고치지 않고 "확인 필요"에 `profile 후보`로만 적는다.
5. 반영한 파일을 `### 반영한 곳`에 모두 적는다.

## 주의

- 앱이 맡긴 정리는 사용자가 없는 자동 실행이다. 질문하지 말고 끝까지 처리하고, 판단이 어려운 것은 "확인 필요"에 남긴다.
- 원문 파일 이름과 위치를 바꾸지 않는다. 앱이 그 경로로 원문을 찾는다.
- 요약의 문체는 `profile/communication/style.md`의 `## 글쓰기`를 따른다.
