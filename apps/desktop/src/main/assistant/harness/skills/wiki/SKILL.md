# 위키

`wiki/`는 비서가 쓰고 관리하는 정리된 지식 저장소다. 목차는 `wiki/index.md`, 이력은 `wiki/log.md`다.

## 페이지 형식

```markdown
# 페이지 제목

> 요점: 이 내용에서 사용자가 가져가야 할 것을 1~3문장으로 적는다. 사용자의 일이나 관심사(`profile/`)와 이어지면 그 연결도 적는다.

## 개요

## 상세 내용

## 관련 개념

- [[다른 페이지 제목]]

## 출처

- `raw/파일 이름.md` 또는 URL
```

- 페이지는 `wiki/<카테고리>/<제목>.md`에 둔다. 카테고리는 `wiki/index.md`의 `##` 섹션이고 폴더 이름은 섹션 이름과 같다. 맞는 카테고리가 없으면 겹치지 않는지 확인한 뒤 새 섹션과 폴더를 만든다.
- 관련 페이지는 `[[페이지 제목]]`으로 적극적으로 잇는다. 새 페이지를 만들 때 기존 페이지는 고치지 않고 새 페이지의 "관련 개념"에서 기존 페이지를 링크한다.

## 자료 정리하기

입력은 `raw/` 파일, 사용자가 준 파일 경로, URL, 대화에 붙여넣은 글이다.

1. 자료를 읽고 무엇에 관한 것인지 파악한다. 서로 다른 주제가 여럿이면 주제마다 페이지를 나눈다. 나눌지 애매하면 나누는 쪽을 고른다. 다만 한 주제를 정의, 예시, 주의점 같은 소제목 단위로 쪼개지는 않는다.
2. 이미 같은 주제의 페이지가 있는지 `wiki/index.md`와 `wiki/` 검색으로 확인한다. 있으면 새로 만들지 않고 그 페이지에 덧붙일지 사용자에게 묻는다.
3. 페이지 형식대로 쓴다. 문체는 `profile/communication/style.md`의 `## 글쓰기`를 따른다. 자료에 없는 내용은 지어내지 않고, 보충한 일반 지식은 출처를 구분해 적는다.
4. `wiki/index.md`의 해당 섹션 표에 `| [[제목]] | 한 줄 요약 |` 행을 더한다.
5. `wiki/log.md` 맨 아래에 `## [YYYY-MM-DD] ingest | 제목`을 더한다.
6. 대화에 붙여넣은 글이나 URL이 원본이면, 원본을 보관할지 사용자에게 묻고 원하면 `raw/`에 저장한 뒤 출처로 적는다.

## 답변을 페이지로 저장하기

지식 질문에 답한 내용이 비교 분석이나 여러 페이지를 엮은 정리처럼 다시 볼 만하면, 페이지로 저장할지 묻는다. 동의하면 위 3~4단계를 따르고 이력은 `## [YYYY-MM-DD] query | 질문 요약`으로 남긴다.

## 점검하기

`wiki/index.md`, `wiki/log.md`, 페이지 목록을 읽고 아래를 확인해 보고서로 보여 준다. 고칠 것은 사용자가 고르면 고친다.

| 항목        | 확인할 것                                                      |
| ----------- | -------------------------------------------------------------- |
| 모순        | 페이지끼리 서로 다른 주장을 하는 곳                            |
| 고아 페이지 | 다른 페이지가 한 번도 링크하지 않은 페이지                     |
| 깨진 링크   | `[[제목]]`은 있는데 페이지가 없는 링크                         |
| 목차 누락   | `wiki/index.md` 표에 없는 페이지, 표에는 있는데 파일이 없는 행 |
| 형식        | 요점, 관련 개념, 출처 섹션이 빠진 페이지                       |
| 채울 것     | 자주 링크되는데 아직 없는 주제, 다음에 읽으면 좋을 자료        |

점검을 마치면 `wiki/log.md`에 `## [YYYY-MM-DD] lint | 점검 요약`을 더한다.
