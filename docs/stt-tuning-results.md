# STT 설정 튜닝 결과 (정답 전사본 CER)

측정일 2026-09-25. 측정 환경 **Apple M3 Pro / 12코어 / 18GB / macOS 25.5**.
실행 방법: `pnpm --filter meeting-stt exec tsx scripts/sttBench.ts <audio.wav> --tag=<이름> [--extra="<whisper 인자>"] [--bin=] [--model=]`
결과는 `scripts/fixtures/output/sttBench.tsv`에 한 줄씩 쌓인다 (git 제외).

지금까지(`docs/model-decisions.md`)는 정답 전사본이 없어 "인식 글자 수"와 사람이 들어 본 몇 구간으로 판단했다.
이번에는 사람이 검토한 전사본으로 **CER(글자 오류율)** 을 재서, whisper 쪽 설정만 바꿨을 때 얼마나 움직이는지 봤다.

## 측정 대상

| 항목   | 내용                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 녹음   | 실제 팀 회의 **102분 55초**, 참석자 8명 안팎, 16kHz mono (`fixtures/audio/jun-meeting.wav`). 발화 RMS −16.9 dBFS로 음량은 충분하다      |
| 정답   | 클로바노트 전사를 사용자가 녹음을 들으며 고치고 검토한 것 (`fixtures/reference/jun-meeting.txt`, 28,514자)                              |
| 채점   | `scripts/cer.ts`. NFC 정규화 → 소문자 → 글자·숫자만 남김(띄어쓰기·문장부호·줄바꿈 제외) → 편집 거리 / 정답 글자 수                      |
| 반복   | 최근 4개 세그먼트 안에 글자가 똑같은 세그먼트가 있으면 반복 환각으로 세고 그 길이를 더한다 (번갈아 도는 고리까지 잡기 위해 4개)         |
| 기준선 | 앱과 같은 조건 — `large-v3-turbo-q5_0`, 음량 정규화, Silero VAD, 앱 동봉 whisper-cli(v1.8.4 정적 빌드), `-bs 5 -bo 5`(whisper-cli 기본) |

정답이 클로바노트 초안에서 출발했으므로 추임새·띄어 말하기 같은 **전사 스타일 차이가 점수에 조금 섞인다.** 절댓값보다 조건 사이의 차이를 본다.
whisper.cpp 출력은 결정적이라 조건마다 1회 측정했다.

## 관찰

**1. whisper 설정으로 얻을 수 있는 폭은 거의 바닥이다.** 반복 고리에 빠지지 않은 조건은 전부 18.7~19.1% 안에 있다.
Homebrew 빌드(−0.16pt), large-v3 + `-mc 0`(−0.12pt)이 가장 낮지만 각각 1.2배, 2.5배 느리고 차이는 전사 스타일 오차 수준이다.
Phase 1에서 음량 정규화 하나로 글자 수가 36% 늘었던 것과 비교하면, 이 녹음에서 디코딩 옵션은 남은 오류를 거의 건드리지 못한다.

**2. 앱의 고품질 옵션(`large-v3`)이 긴 회의에서 무너진다.** 60분 이후 "6월이." / "한."을 번갈아 내는 고리에 빠져
**39분(2,338초)** 을 날리고 CER이 44%가 됐다. 0~60분 구간은 turbo와 글자 수가 같다. 이전 창의 출력이 다음 창의 문맥으로 넘어가면서
스스로를 강화하는 고리이고, `-mc 0`을 주면 사라진다(18.77%). 금토로 71분 녹음에서 turbo가 1,103초 반복한 것과 같은 계열로 보인다
(`references/pitfalls.md`). 고품질 옵션을 고른 사용자가 가장 나쁜 결과를 받는 셈이라 가장 급한 문제다.

**3. `-mc 0`은 CER을 0.23pt 올리는 대신 반복 환각을 거의 없애고 16% 빨라진다.** 문맥을 넘기지 않아 창 경계에서 문장이 조금 어색해지는 비용이 있지만,
한 번 빠지면 수십 분을 날리는 고리를 끊는 안전장치로는 싸다. 금토로 71분(turbo 1,103초 반복)에서도 같은 효과인지는 아직 재지 않았다.

**4. VAD를 민감하게 하면 놓친 말(삭제 −445)은 줄지만 반복·삽입이 더 늘어 상쇄된다.** 잡음 구간을 말로 보고 넘기면서 환각이 는다.
기준선에서 20~49초 세그먼트가 한두 마디로 뭉개진 6곳은 VAD 조정으로 풀리지 않았다.

**5. `-sns`는 오히려 나빠진다** (삭제 +901). 한국어 말 일부를 비음성 토큰으로 억제하는 것으로 보인다. 쓰지 않는다.

## 금토로 71분 재확인 (turbo)

기존에 반복 환각이 가장 심했던 발표 녹음(`docs/phase5-refine-results.md`, 정답 전사본 없음)으로 `-mc 0`을 다시 쟀다.

| 기준선      | 21,860    | 486개 · 1,034초 | 250초     |

반복에 먹혔던 구간이 실제 말로 채워져 글자 수가 3% 늘었다.

## 용어 프롬프트 (인식 단계, 2026-10-01)

앱 전역 용어 사전 56개의 용어 이름을 쉼표로 이어 `--prompt`로 주고 `--carry-initial-prompt`를 켰다 (218토큰, `sttBench.ts --prompt-file`).

| 조건                            | CER        | 치환  | 삭제  | 삽입 | 인식 글자 | 반복 환각  | 처리 시간 |
| ------------------------------- | ---------- | ----- | ----- | ---- | --------- | ---------- | --------- |
| 기준선 `-mc 0` (앱 설정)        | 19.12%     | 2,553 | 2,365 | 533  | 26,682    | 4개 · 6초  | 238초     |
| 프롬프트 + carry, `-mc 0`       | 19.12%     | —     | —     | —    | —         | —          | 292초     |
| **프롬프트 + carry, `-mc 219`** | **18.47%** | 2,591 | 2,107 | 569  | 26,976    | 5개 · 17초 | 272초     |

- **`-mc 0`이면 프롬프트가 통째로 꺼진다.** whisper.cpp는 `n_max_text_ctx > 0`일 때만 프롬프트를 붙인다. 출력이 기준선과 바이트 단위로 같았다.
- `-mc`를 프롬프트 토큰 수 + 1로 주면 매 창에 용어만 붙고 직전 출력 문맥은 0이 된다. 반복 고리를 끊는 `-mc 0`의 의도는 유지된다.
- 이름 용어가 살아난다: 루덴스 4→10(정답 14), 흑곰 0→3, 시지프 0→2, 이스타 1→2, 유월 0→1. 반면 "아지"가 정답 1곳보다 많은 3곳에 나와 오삽입 가능성이 있다.
- 프롬프트 문자열 유출은 없었다. 이 회의에는 라틴 문자 용어가 거의 나오지 않아 그쪽 효과는 재지 못했다.
- `-t 3`(조용히 처리)로 측정해 처리 시간은 기준선(앱 기본 스레드)과 직접 비교할 수 없다.

## 다른 STT 모델 비교: Phonon-2 (2026-10-05)

Fermion Research가 공개한 [Phonon-2](https://www.fermionresearch.com/research/phonon-2/)(NVIDIA Parakeet TDT 0.6B v3 파생, 164MB, CC-BY-4.0,
MLX·CPU·CUDA 실행)를 사용자 요청으로 쟀다. 공식 카드는 **영어 전용**이고 바탕 모델 v3도 유럽 25개 언어만 지원한다. 측정은 한국어를 실제로 못 받아쓰는지 확인하려는 것이다.

관찰:

- **한국어를 영어 단어와 로마자 음차로 적는다.** 한글 출력이 0자라 CER이 100%다. 음차가 앞부분 발음을 어렴풋이 따라가지만("Kongjug inye" ← 경주 지역 인사) 글자로 되돌릴 수 없다.
- **문장을 통째로 빠뜨린다.** 내부 30초 창마다 앞쪽 한두 문장만 내고 나머지는 비운다. 61.9~88.2초 창은 출력이 아예 없다. 삭제 474자가 여기서 나왔다.
- 실제 회의 녹음(`jun-meeting.wav`) 첫 60초도 같다: "Or can they go? Or time passing to the ground to wait on the money to pay some is a soldiers we can mutual." (디코딩 1.65초)
- 102분 전체를 한 번에 넣으면 12분이 넘도록 출력 없이 MLX GPU 대기에서 멈춰 중단했다. 원인은 조사하지 않았다.
- 속도(실시간 40배)와 크기(164MB)는 whisper turbo보다 낫지만 한국어를 지원하지 않아 쓸 수 없다. **STT 엔진 결정(whisper.cpp)은 바꾸지 않는다.** 한국어·다국어 버전이 나오면 같은 `zeroth100`과 `jun-meeting`으로 다시 잰다.

## 결정

**모든 whisper 모델에 `-mc 0`을 준다** (2026-09-25 사용자 결정). 반복 고리를 끊는 효과(1,034초 → 25초, 2,338초 → 2초)와 속도 이득(16~18%)이
CER 비용(+0.23pt)보다 크다. `SKILL.md` 결정 표·`references/pitfalls.md`·`references/architecture.md`에 반영했다.

## 녹음 중 STT: 조각마다 인식 (2026-10-25)

정지 뒤 기다리는 시간을 줄이려고 녹음 중에 STT를 미리 돌리는 안을 쟀다 (2026-10-25 사용자 요청). 조각이 찰 때마다 whisper-cli를 돌리면 정지 뒤에는 마지막 조각만 남는다.

| 항목   | 내용                                                                                                                                                                                                                                                                                                                                                 |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 자르기 | 녹음기와 같은 청크(8,192샘플 = 0.512초)를 라이브 받아쓰기 판정(`pushLiveChunk` — 소음 바닥 +9.5 dB 초과나 −34 dBFS 이상이면 말소리)으로 가르고, 조각이 **20초 이상이면 다음 쉼 청크에서, 25초에 닿으면 강제로** 자른다. 쉼은 녹음기가 보는 원본 음량으로 찾는다 (`src/main/audio/sttChunks.ts`, 측정 때는 같은 규칙의 `scripts/sttChunks.ts`)        |
| 인식   | 조각마다 whisper-cli를 새로 띄운다(모델 로드 포함). 인자는 앱 파이프라인과 같다 — turbo, Silero VAD, `-mc 0`. 용어 프롬프트는 양쪽 다 없음                                                                                                                                                                                                           |
| 정규화 | **전체 정규화**: 파일 전체로 정규화한 뒤 자른다(게인이 지금과 같아 자르기 효과만 본다). **조각별 정규화**: 원본을 잘라 조각마다 따로 정규화한다(녹음 중에는 전체 음량을 모르므로 실제로 할 수 있는 쪽)                                                                                                                                               |
| 조건   | `-t 3` + `nice -n 15`, 실행 하나씩 순차, M3 Pro. 기준선(파일 전체 한 번)도 같은 조건으로 다시 쟀다                                                                                                                                                                                                                                                   |
| 녹음   | 102분 회의(`jun-meeting`, 정답 28,514자)와 71분 발표(`geumtoro`, 원거리 마이크, **정답 없음**)                                                                                                                                                                                                                                                       |
| 실행   | `nice -n 15 pnpm --filter meeting-stt exec tsx scripts/sttBench.ts <wav> --tag=<이름> --chunked=global\|each --extra="-t 3"` (조각별 시간은 `<출력>.chunks.json`). 정답이 없는 71분은 `--ref=scripts/fixtures/output/geumtoro.full-t3.txt`로 전체 한 번 결과와의 차이를 쟀고, 102분의 상호 차이도 같은 방식(`computeCer`에 한쪽 결과를 정답으로)이다 |

### 관찰

1. **잘라서 인식해도 CER이 나빠지지 않는다** (19.12% → 18.64%). 조각의 30%가 말 중간에서 강제로 잘렸는데도 그렇다.
   잘린 자리의 단어가 틀리는 곳은 있다 — 71분 2,055.7초 경계 "꼭 돌아야 되는 양"이 "꼭 / 끌어야되는 양"이 됐다. 경계 다섯 곳을 골라 본 중 한 곳이다.
2. **조각별 정규화는 전체 정규화와 CER이 같다** (18.64% 둘 다). 원거리 71분에서는 글자가 조금 더 나온다(22,634 vs 22,289).
3. **원거리 녹음에서는 쉼을 거의 못 찾는다.** 71분 발표는 청크 RMS의 소음 바닥이 −52 dBFS, 중앙값이 −47.7 dBFS라 라이브 판정이 말소리로 본 청크가 10%뿐이다.
   그래서 207개 중 177개(86%)가 20초를 넘긴 첫 청크(20.5초)에서 "쉼"으로 잘렸다 — 사실상 쉼을 보지 않고 일정 간격으로 자른 것이다. 그래도 결과가 무너지지 않았고 반복 환각은 오히려 줄었다(25초 → 3·13초).
4. 반복 환각은 102분에서 조금 늘고(6초 → 16·22초) 71분에서 줄었다(25초 → 3·13초). 조각 결과는 둘 다 녹음 길이의 0.4% 미만이다.
5. **정지 뒤 STT 대기가 3~4분에서 마지막 조각 하나(2초 안쪽)로 준다.** 녹음 중에는 조각이 녹음 길이의 15% 안에 끝나 밀리지 않는다.
6. 대가는 **GPU 처리 시간 합 1.8~1.9배**다. 조각마다 모델을 새로 읽어서(처리 시간 합의 차이를 조각 수로 나누면 조각당 약 0.7초) 생기고, 녹음 시간에 흩어져 있어 대기 시간에는 들어가지 않는다. 모델을 상주시키는 `whisper-server`로 줄일 수 있지만 지금은 하지 않는다.
7. 재지 않은 것: 용어 프롬프트를 붙인 조각, 녹음 중 다른 GPU 작업(앞 녹음의 처리 잡·라이브 보기)과 겹칠 때. 고품질 모델은 아래 "고품질 모델의 조각 시간"에서 쟀다.
