# 녹음 품질과 인식 성능 측정

측정일 2026-10-02. 측정 환경 **Apple M3 Pro / 12코어 / 18GB / macOS 25.5**. 실험은 3스레드 + `nice -n 15`, 순차 실행.

"녹음 품질 자체가 나빠서 인식이 망가지는 경우를 앱이 알려 줄 수 있는가"를 정하기 전에, **어떤 지표가 인식 품질과 실제로 같이 움직이는지**를 먼저 쟀다.
녹음 중 경고와 사후 품질 표시(`references/roadmap.md` "녹음 품질 안내")의 임계값은 이 문서의 수치에서만 가져온다.

실행 방법:

```bash
nice -n 15 pnpm --filter meeting-stt exec tsx scripts/qualitySurvey.ts survey      # 1절
nice -n 15 pnpm --filter meeting-stt exec tsx scripts/qualityDegradeBench.ts       # 2절 (output/quality/degrade.tsv)
nice -n 15 pnpm --filter meeting-stt exec tsx scripts/qualitySurvey.ts speakers    # 3절
```

## 지표 정의

전부 **50ms 프레임 RMS**에서 나온다 (음량 정규화와 같은 프레임, `scripts/qualityMetrics.ts`).

| 지표      | 정의                                     | 뜻                                                                          |
| --------- | ---------------------------------------- | --------------------------------------------------------------------------- |
| 발화 음량 | 프레임 RMS의 90퍼센타일 (dBFS)           | 음량 정규화가 −20 dBFS로 맞추는 바로 그 값                                  |
| 바닥 잡음 | 프레임 RMS의 10퍼센타일 (dBFS, 최소 −96) | 아무도 말하지 않을 때의 소리 크기                                           |
| 폭        | 발화 음량 − 바닥 잡음 (dB)               | 말소리가 바닥 잡음 위로 얼마나 솟는지. 진짜 SNR이 아니라 음량 분포의 폭이다 |
| 클리핑    | 풀스케일(±32700 이상)에 닿은 샘플 비율   | 입력이 너무 커서 파형이 잘린 정도                                           |
| 무음      | −70 dBFS보다 작은 프레임 비율            | 디지털 무음(음소거, 꺼진 채널)                                              |

**측정 오차.** 감쇠 −12~−30dB는 정규화 뒤 사실상 같은 소리인데 CER이 13.4~14.5%로 흩어진다. 이 발췌에서 **±1%p 안의 차이는 읽지 않는다.**

### 관찰

**1. 음량이 작은 것 자체는 문제가 아니다.** 발화 음량이 −52 dBFS까지 내려가도(원본보다 36dB 작음) CER이 그대로다. 음량 정규화가 제 몫을 한다.
게인 상한(+30dB)에 걸리는 −58 dBFS에서야 +1.5%p 오른다. "목소리가 작다"는 경고는 **−50 dBFS 아래에서만** 의미가 있다.

**2. CER을 정하는 것은 "폭"이다.** 잡음이 커질수록(폭이 줄수록) CER이 한 방향으로 오른다.

| 폭         | 핑크 잡음 CER | 떠드는 소리 CER | 원본(14.3%) 대비 |
| ---------- | ------------- | --------------- | ---------------- |
| 34dB(원본) | 14.3%         | —               | —                |
| 약 25dB    | 19.2%         | —               | 1.3배            |
| 약 21dB    | 23.0%         | 29.1%           | 1.6~2.0배        |
| 약 16~18dB | 31.6%         | 39.9%           | 2.2~2.8배        |
| 약 11~14dB | 43.3%         | 60.6%           | 3.0~4.3배        |
| 10dB 이하  | 60~81%        | 85.6%           | 사실상 못 씀     |

전체를 30dB 줄여도 폭이 같으면 CER이 같다(핑크 10dB 아래: 43.3% vs 감쇠까지 한 것 43.1%). **음량이 아니라 폭을 봐야 한다.**
1절에서 원거리 녹음이 전부 폭 20dB 미만이었던 것과 맞물린다 — 원거리 녹음은 이 표에서 CER이 2배 이상인 구간에 있다.

**3. 사람 목소리 잡음이 더 해롭다.** 같은 폭에서 떠드는 소리가 핑크 잡음보다 6~17%p 나쁘다. 치환이 크게 는다(배경 말소리를 받아 적는다).
폭 지표는 잡음의 종류를 구분하지 못하므로, 임계값은 "최소 이만큼 나쁘다"로 읽는다.

**4. 클리핑은 심해야 문제다.** 샘플의 2.8%가 잘려도 CER이 그대로이고(15.5%), 17.7%가 잘려야 +7%p다. 클리핑 경고는 **잘린 샘플이 몇 %를 넘을 때만** 띄울 일이다.

**5. 대역 제한(블루투스 통화 모드)은 +4.8%p.** 폭·음량 지표에는 전혀 드러나지 않는다(34.1dB, −16.4). 소리 지표가 아니라 **장치 종류**로 알려야 한다.

## 3. 실제 회의 안에서: 화자·턴 음량별 CER

| 턴의 발화 음량 (60자 이상) | 턴  | 글자   | CER       | 삭제  |

  그 사람에게는 바닥 잡음 대비 폭도 그만큼 좁다(같은 방, 같은 잡음). 다만 화자마다 말버릇·발음이 달라 음량만의 효과라고 단정할 수는 없다(화자 7명).
- 시간대(5분 단위)별 CER은 10.8~~36.3%로 크게 흔들리지만 발화 음량은 −15.8~~−18.8로 거의 같다. 시간대별 차이는 음량이 아니라 **누가, 얼마나 짧게 주고받았는지**에서 온다
  (CER이 30%를 넘는 50분·90분·100분대는 턴이 가장 촘촘한 구간이다 — 5분에 37~38턴, 마지막은 3분에 16턴. 나머지는 대부분 5분에 20턴 이하).

## 4. 앱의 캡처 경로를 거친 녹음

1~3절의 녹음은 전부 앱 밖에서 만든 파일이다. 앱이 직접 녹음한 소리는 Chromium의 음성 처리(에코 제거·잡음 억제·자동 게인)를 거치므로
같은 지표·같은 임계값이 통하는지 따로 확인했다.

**방법.** Chromium의 가짜 마이크(`--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>`)로 WAV 파일을 마이크 입력처럼 넣고,
빌드한 앱에서 평소대로 녹음했다(위젯의 `getUserMedia` → AudioWorklet → main의 WAV). Electron에서는 오디오 서비스 샌드박스가 파일을 못 읽어 무음이 되므로
`--disable-features=AudioServiceSandbox`가 필요하다. 입력은 D1 **앞 5분(301초, 정답 1,731자)** 의 2절 조건들이고, 녹음된 WAV를 2절과 같은 경로로 채점했다.
마이크 제약 변형은 소스를 건드리지 않고 빌드 산출물의 제약 객체만 바꿔 녹음했다. 구동 스크립트는 저장소에 넣지 않았다(스크래치).

지금 앱의 제약은 `echoCancellation: true, noiseSuppression: true`이고 `autoGainControl`은 적지 않아 **Chromium 기본값(켜짐)** 이다(트랙 설정으로 확인).

- **앱을 거치면 인식이 나빠진다.** 다섯 조건 중 네 조건에서 3.6~7.2%p 나쁘고, 늘어난 오류는 대부분 **삭제**다(원본 104 → 120, 감쇠 93 → 222, 핑크 20 205 → 340자). 말소리 일부가 깎여 나간다.
- 자동 게인이 음량을 맞춘다. −47 dBFS로 넣어도 −17 dBFS로 녹음된다. 앱 녹음에서 "목소리가 작다"는 경고는 띄울 일이 없다.
- 잡음 억제가 바닥 잡음을 17~20dB 끌어내려 **폭이 부풀려진다**(36.6 → 53.6, 20.8 → 40.9). 폭의 순서는 유지되지만 2절의 임계값을 그대로 쓸 수 없다.

### 4-2. 제약을 바꿔 가며 (같은 입력)

| 입력                  | 직접   | 지금 (에코·잡음·게인) | 잡음 억제만 끔 | 잡음 억제·게인 끔 | 전부 끔 |
| --------------------- | ------ | --------------------- | -------------- | ----------------- | ------- |
| 원본                  | 12.94% | **16.58%**            | 13.69%         | 13.06%            | 14.67%  |
| 감쇠 −30dB            | 13.00% | **19.93%**            | 13.86%         | 13.11%            | 15.14%  |
| 핑크 잡음 20dB 아래   | 31.25% | **37.49%**            | 30.96%         | 32.06%            | 29.75%  |
| 떠드는 소리 15dB 아래 | 58.41% | 56.15%                | 52.80%         | 53.61%            | 52.40%  |

폭(dB)도 잡음 억제를 끄면 직접 경로와 같아진다 — 원본 38.2, 감쇠 38.3, 핑크 20 22.7, 떠드는 소리 18.0 (직접 36.6 / 36.5 / 20.8 / 18.1).

- **원인은 잡음 억제 하나다.** 잡음 억제만 꺼도 네 조건 모두 직접 경로 수준으로 돌아오고(차이 −5.6~+0.9%p), 지금 설정보다 **2.9~6.5%p 낮다.**
  Whisper는 잡음이 섞인 소리로 학습돼 잡음 자체에는 강하고, 잡음 억제가 말소리까지 깎는 쪽이 더 해롭다.
- 자동 게인은 영향이 없다(켬 13.69 / 13.86 vs 끔 13.06 / 13.11, 오차 안). 켜 두면 −47 dBFS 입력을 −17로 올려 주고, 꺼도 음량 정규화가 같은 일을 한다.
- 에코 제거도 영향이 없다(오차 안). 이 실험은 스피커 재생이 없어 에코 제거가 할 일이 없는 조건이다.

**한계.** 5분 발췌 하나(1,731자, 측정 오차 ±1.5%p 안팎)이고, 가짜 마이크는 파일의 디지털 신호를 그대로 넣는다 — 실제 마이크에서 자동 게인이 시스템 입력 음량을 조절하는 효과는 재지 못한다.
